### Поправка к аудиту TLS

Вывод U1 о небезопасном TLS по умолчанию был ошибочным: в закреплённом
`libs/hbb_common/src/tls.rs:84–87` при выключенном
`allow-insecure-tls-fallback` всегда возвращается `Some(false)`.
`option2bool` включает этот allow-параметр только для значения `Y`.
Поэтому сохранены безопасный default, strict-клиенты и явно разрешаемое
исключение для существующих конфигураций. Новые audit-ignore не добавлялись.

## Регрессионная поверхность

- `src/hbbs_http/http_client.rs`: конструкция sync/async клиентов, proxy/TLS
  verifier errors и длительность connect/HEAD. Возврат Result необходим,
  чтобы не подменять сетевую политику. Правила выбора TLS/явного исключения
  сохранены; streaming downloads не получили общего 12-секундного ограничения.
- `src/common.rs`: четыре места создания HTTP-клиента теперь передают ошибку
  наверх через `?`; логика authenticated TCP fallback не переписана. Его
  транспорт также использует настроенный прокси и не обходится прямым TCP.
- `src/hbbs_http/account.rs`: создание клиента и lock при прогреве OIDC;
  auth counters, cancellation policy и формат протокола не менялись.
- `src/hbbs_http/record_upload.rs`: при ошибке клиента поток останавливается
  с диагностикой вместо обхода прокси; запись на диск этим не отключается.
- `src/privacy_mode/win_virtual_display.rs`: пять начальных структур и текст
  ошибок API. Алгоритм переключения/восстановления дисплеев не переписан.
- Четыре formatter-файла: только порядок импортов, переносы и пробелы.
- CI workflows: concurrency, артефакты, автоматические проверки и gate;
  Windows/Android signing выполняется после прежнего environment approval.
- Cargo.lock: только две patch-версии rand, checksums/ссылки и автоматически
  созданный формат v4. Все активные toolchains его поддерживают. Legacy
  Sciter Rust 1.75 уже требует отдельного старого dependency graph.

## Как загрузить именно в свой форк

Origin проверен: `https://github.com/Elyor1977/rustdesk.git`.
Записанная предыдущая ревизия origin/master:
`8a5ad158aeb7158826c43496d46277acde35bbbc`.
Обычный push master будет отклонён, поскольку восстановлена история.
Сначала отправить backup, затем master с **точным lease**:

```powershell
git push origin backup/master-before-audit-fixes-2026-10-05
```

Только если первая команда успешна:

```powershell
git push --force-with-lease=refs/heads/master:8a5ad158aeb7158826c43496d46277acde35bbbc origin master
```

Если lease отклонён — не использовать --force: удалённый master изменился,
нужно сначала изучить новые commits. Upstream не отправлять; PR не нужен.
